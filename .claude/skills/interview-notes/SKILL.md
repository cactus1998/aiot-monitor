# 面試講稿

目標：讓使用者能在 2–5 分鐘內講清楚一個功能，並接得住追問。內容必須以實際程式碼為依據，不能虛構沒有實作的特性。

## 步驟

1. 讀 `docs/PRD-<slug>.md` 與實作檔案（從 PRD 的「資料與介面」與開發紀錄找到路徑；前後端都要看）。沒有指定 slug 時，列出 `docs/TODO.md` 中已完成的項目讓使用者選。
2. 對照 `docs/PRD-aiot-monitor.md` 的「考點對照」，標出這個功能能回答哪些考點。
3. 找出真正的技術重點：資料流、儲存設計、降採樣與效能、競態處理、即時連線、型別與 schema 共用、無障礙、測試方式。
4. 寫入（或更新）`docs/interview/<slug>.md`，使用下方模板。已存在時保留使用者手寫的內容，只更新過時段落。
5. 程式碼有弱點（例如沒處理 race condition、沒清理 listener）時，不要掩飾，寫進「已知限制」，並在回覆中建議修正方式。
6. 回覆使用者：一句話總結，加上 3 個最可能被追問的問題。

## 模板

```markdown
# <功能標題>

## 30 秒電梯簡報
<做了什麼、解決什麼問題、最亮的技術點>

## 對應面試考點
- <例如：API → 表格 + 折線圖；資料存在哪裡>

## 問題背景
<為什麼需要；naive 做法會遇到什麼問題（例如 24 小時原始資料直接畫，點數過多造成卡頓）>

## 資料流
<從 simulator / DB 到畫面，標出檔案路徑>

## 實作重點
- <重點：檔案與函式，例如 `apps/api/src/routes/series.ts` 的分桶 SQL>

## 設計決策與取捨
| 決策 | 替代方案 | 為什麼選這個 |
|------|----------|--------------|

## 效能數據
<量測方式與數字>

## 已知限制與可延伸方向
- <限制> — <怎麼改進>

## 面試官可能追問
**Q: <問題>**
A: <簡潔、口語的回答>

（至少 5 題，涵蓋：原理、邊界情況、效能、測試方式、規模放大 100 倍或接真實機台時怎麼辦）

## 相關知識點
<例如 event loop、HTTP/1.1 連線數與 SSE、SQLite 索引、reflow/repaint、Vue reactivity>
```

## 寫作原則

- 繁體中文，技術名詞保留英文原文。
- 回答要口語、可以直接講出口。
- 引用程式碼時標示檔案路徑，方便展示時直接打開。
